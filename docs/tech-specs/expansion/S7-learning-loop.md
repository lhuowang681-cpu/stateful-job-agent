# S7 · 有来源的学习观察、用户核对与复习闭环

版本1.1，2026-10-22。先以1.0写实施前合同；当前工程/规则真实HTTP/PG来源/浏览器verified，真实Qwen闭环失败保留。基线CURRENT_SPEC0.7、487通过/4限定跳过；最后517通过/4既有限定跳过。实体、API、真实失败、源码锚点与30分钟导读见[EXPAND-S7](../../devlog/EXPAND-S7.md)。旧面试有结束后复盘/weakness检索，但没有持久学习观察、用户纠正/撤回/复习队列；不把一次答不好固化为能力画像。

## 实体与边界

学习域与面试同一SQLite事务域，复用InterviewRepository的owner/来源/版本/引用校验；项目源可在PG，跨域仍重新校验，不宣称分布式事务。仅从complete且已答的turn生成LearningObservation，活场次/未答不导入，不泄露rubric到进行中视图。

针对单要点的追问只生成该focus的观察，避免把本轮未被询问的其他要点再标为缺失。全局暂停只停止复习建议，单条暂停同时阻止从该条新建练习；已创建的面试仍沿用原暂停/结束操作。纠正作为独立用户自述；若不再使用原评价作学习依据，需显式撤回该题评价。

观察按(owner,session,question,point,source_fingerprint)确定ID/去重。保存知识点、题面/题ID、完整rubric与aliases指纹、回答/回答hash、评价依据/模式/方法版本/模型配置、发生时间、简历版本、固定引用定位/版本/hash与来源场次。引用原文不额外复制进学习表；用户数据只在既有私有域，不发外部服务，不向量化全部记忆。

原评价与用户自述分开：原状态可为词面定位/未识别、模型correct/incorrect/uncertain等；用户只能明确标“需练习/不确定/自述已理解”并写纠正说明，不能把模型结果改成现实真实性或个人贡献。多次一致观察仅在记录条件相同且来自不同场次时累计，显示次数/条件，不称掌握或教学效果。用户偏好独立存储（节奏1—30天、每日1—20、是否暂停/纳入新观察），来源明确为用户；默认规则另标默认。

## 用户控制、生命周期与并发

- 用户可查看、确认、纠正、暂停/恢复、调整复习时间、标记本次复核、删除观察；revision CAS与请求键保证控制幂等，不改原回答/评价/简历。删除保留无正文tombstone，避免同源同步后自动复活；源面试/简历删除通过FK级联清除该学习记录及相关控制日志。
- 用户可撤回某次题目的评价作为学习依据：保留原面试历史，独立withdrawal记录使该题观察失效/不入队列/不再驱动weakness；复盘明确撤回，不静默改写原评价。撤回不等于模型评价被客观证伪。
- 每次读取或再次练习重新核owner、源状态/hash、版本与引用；源删除/损坏/评价撤回/指纹变化显示失效并隐藏回答/评价内容，不继续提供作练习依据。项目删除跨域无FK，读时失效，不复活已删除项目。学习表不声称同步物理删除旧面试内历史引用。
- 新简历head与观察旧版本不同，保留原观察并标历史；默认不继续旧版练习，用户明确允许原版才可开始。90天未核对的旧观察标过期/需重新核对，不自动推定忘记；纠正/确认不篡改原发生时间。
- 单owner最多2000观察（含tombstone），单场最多100条；有界列表/队列/事务内按场次缓存来源读取，防止每个知识点重复开连接。共享当前SQLite事务校验引用，避免重现S3嵌套新连接死锁。

## 复习与再次练习

规则队列至少新学/待复习/已复核，暂停/失效/历史待确认另列；理由可见，不伪装训练模型。未核对的观察先确认，用户调整时间优先；每日条数与全局暂停由明确偏好控制。

每日上限按上海日期与owner下当前仍保留的不同观察的最近复核时间计算；跨简历共用额度，撤回/来源失效不退款。达到上限当天不继续自动建议，次日重置，手动查看/练习仍由用户决定。单条删除不保留其复核时间来维持配额。新回答记录提交时间，旧面试缺少该字段时明确使用建场时间回退，不假造答题时间。

新增按观察发起的练习，复用原InterviewRepository/InterviewEngine图和原答题API，不创建第二套面试器。复用该观察的题面/完整rubric/固定引用及模式条件，选择对应知识点；新question_id、新场次、空历史回答，活视图仍不展示答案。用户可选规则或已配置模型，模型同意仍走原门禁，不能自动发起付费/外发。历史版本需显式允许。

请求通过可信owner查观察、原版本/JD/来源，不能由模型传任意scope。学习派生状态进入请求/执行身份，旧无学习字段的历史hash保持兼容。新场次完成后产生新观察；仅题面/focus/完整rubric/引用/简历与JD/记录模型配置/评价方法相同时标同条件参考；不同条件不计算提升，原模型判断不等于客观真值。用户纠正/撤回的旧观察不作未经说明的比较基准。

## API/界面与验证

从结束复盘“保存学习观察”进入原面试面板下的学习记录/偏好/复习列表，可确认/纠正/暂停/删除/撤回依据/安排与再次练习；不自动标用户已学会。服务端实际路由/数据字典按最终代码回填。

验收：owner隔离、同步去重/内容变化、控制CAS/请求幂等、tombstone不复活、偏好来源与队列规则、撤回/版本变化/引用删除/过期、同/不同条件比较、活视图无rubric、默认禁止外发。真实HTTP完成“回答→结束→观察→核对→复习→新场次→新观察”；SQLite与已配置PG项目源分别验证引用失效。模型/规则/人工分层；自动化合成用户点击不称真人掌握。
