## 分组与计分

- JD：原有 WorkbenchMatcher 本地预检查为规则基线；真实模型 direct-context 为 LIVE_PENDING。原子集合按人工标签计算 micro Precision/Recall/F1；精确原文切片相等为 span 正确，缺证据不算无能力。
- 简历：原有完整摘录协作为基线，后续局部改写另分组。按每个新增断言检查来源与语义范围；来源命中率不能替代事实正确率。未经人工盲评不能宣称质量提升。
- 检索：README-only、平面文本、符号优先、语法/混合/关系展开。相同 query、候选库、top-k=5；Recall@5=命中相关证据数/全部相关数，MRR=首个相关排名倒数；跨文件完整率=必要文件全部命中的题比例。无相关答案的题单独计空结果/误召回，不加入 Recall 分母。
- Agent：single、sequential、bounded feedback 使用相同输入、模型标识、温度0、总调用上限6、输出上限1600；输入长度与实际消耗另记。规则替身只验证机制，不用来证明 LLM 收益。缺少真实模型授权时结果 LIVE_PENDING。
- 延迟记录每条 wall time；p50/p95 只对实际样本统计，同时记录失败、超时、调用数、token、未知成本。不能把未知费用写0。
- Code：源文件、符号、调用关系的 gold 分开。静态可解析边不是运行时调用证明。正确引用必须匹配 owner、snapshot、路径、hash、行范围和原文；旧 snapshot 引用不能挪到新版。
- 面试：问题相关性、追问相关性、覆盖、参考答案泄漏分开；自动规则只检查界限，真实教学效果需要人工或真实模型评审。
